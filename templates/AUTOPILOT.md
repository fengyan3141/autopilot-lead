## 1. 三档规则

| 档 | 包括 | 做法 |
|---|---|---|
| **自动档**（不问） | 改代码、跑测试、写日志、commit、push、按既有流程部署（部署前备份、比对、写回滚） | 直接做，结果进看板 |
| **先做后看档** | 需要判断、但可逆的事（文案取舍、数值、规则边界、技术选型） | 问 advisor 一句 → 按结论做 → 记 §7 台账（用户已看 = 否，写清怎么撤） |
| **硬停档**（等用户） | 见下方硬停清单 | 通知【要你拍板】，给推荐和回复方式；不等回复，先做别的 |

**硬停清单**（按项目增减，改动记台账）：
1. 花钱（买服务、升级套餐、付费 API 超出既定额度）；
2. 对外发布（官网、法务文本、公告、应用商店提交）；
3. 删线上数据、改写线上数据的迁移；
4. 换密钥 / 改权限；
5. 放宽安全或合规规则（任何「从拦截改为放行」）；
6. 推翻台账里已明文拍板的口径；
7. 不可逆、且影响对外承诺的操作。

**拿不准归哪档，按硬停。** 只读查询、本机测试栈都算自动档。

## 3. 硬规矩

1. **只有总控 commit / push。** 工人不 commit、不 push、不 merge。每次 commit 完顺手 `git push origin {{BRANCH}}`。
2. **派工前主目录必须干净并已 commit**：worktree 从 HEAD 分出。提示词写明基点 commit；**工人开工第一步 `git log -1` 核对基点**，不符就停下回报。
3. **工人不许扩范围**：顺手发现的问题记日志「没做 / 待拍板」，不改。
4. **审查打回一次**，意见带具体指令；第二次仍不过 → 停，报用户。
5. **续做只能 SendMessage 原工人**：新派的工人被隔离在自己的 worktree，进不去别人的目录。
6. **同一目录同一时间只有一个工人。** 并行上限：（按槽位写，例：app 1 + 其他 2）。
7. **重活排队**：编译、模拟器、容器、大批量测试经 `bash tools/build-slot.sh -- <命令>`。
8. **测试输出不进上下文**：一律 `> build-<字母>/<名>.log 2>&1`，只读 `grep` 汇总 + `tail`；修红只跑红的，全绿后再跑一次全量收尾。
9. **线上数据库一律只读事务**（`begin transaction read only; …; rollback;`），除非任务本身就是上迁移。
10. **部署只在主目录、只部署已合并的 commit**；部署前备份、比对、写回滚方法。
11. **密钥不进仓库、日志、提示词、通知。**
12. 脏工作区禁用 `git checkout` / `git restore` / `reset --hard`；撤销自己的改动先 `cp` 备份。
13. **预算**：每个工人任务命令上限 80、token 预算写在提示词开头；到 80% 让它收尾交活。逐条处理数据的活必须「写脚本一次跑」。
14. 撞到用量上限就停等，恢复后从看板「进行中」续。

## 4. 角色与模型

| 角色 | 子代理 | 模型 | 说明 |
|---|---|---|---|
| 总控 | 本会话 | 最强 | 派工、合并、commit、部署、通知 |
| 审查 | `reviewer` | 最强 | 只读，按 §6 |
| 拍板顾问 | `advisor` | 最强 | 只读，给结论不给选项 |
| 工人 | `worker-<槽>` | 最强 | worktree 隔离 |
| 机械活（截图、分诊、格式整理） | 按需新建 | 便宜模型 | 修 bug 与审查不降级 |

`.claude/agents/` 新建或改动后要**新开会话**才会被识别。识别不到时用 `general-purpose` + `isolation: worktree`，提示词第一句让它先读对应 `.claude/agents/<角色>.md` 并遵守。

## 5. 任务提示词模板

存 `docs/prompts/<序号>-给<工人>-<题目>.md`。

```
目标：一句话。
基点：{{BRANCH}} @ <commit>（开工先 git log -1 核对）。命令上限 80，预算 <N>。

## 先读（精确到节，不重新调研）
1. …

## 做什么
1. …（文件、改法、边界）
- 逐条处理数据的条目明写「写脚本一次跑」

## 不许碰
- 目录 / 文件 / 线上对象；不 commit、不 push

## 测什么
- 跑哪些测试；输出重定向到 build-<字母>/，只读汇总
- 反向验证：临时改坏哪一处、哪条测试必须红，改回后复绿，确认没留变异标记
- 有部署的：工人备好备份、回滚、冒烟期望；部署由总控合并后在主目录做

## 日志 docs/audit/FIX_LOG_<字母>_<日期>.md
§0 一眼看完表（每件事一行 + 和提示词不一样的地方）/ 每件事的文件与改法 / 测试 / 反向验证 / 没做·待拍板 / 需要用户做的验收步骤
```

日志字母顺排（A、B、…、Z、AA…），看板上记已用到哪个。

## 6. 审查清单（reviewer 逐条回答 是 / 否 / 证据）

1. diff 只落在提示词「允许范围」内（`git diff --stat` 对照）。
2. 日志 §0 每一行都能在 diff 里找到；diff 里每处改动在 §0 都有交代。
3. 提示词要求的测试真的跑过，命令和结果贴在日志里。
4. 测试有反向验证（红过、改回、复绿、变异标记清零）；没有为变绿放宽断言。
5. 界面改动附截图，且与期望一致。
6. 部署有备份、比对、回滚方法。
7. 没有与 §7 台账已拍板口径相反的改动。
8. 没有密钥、没有 commit、没有越权的线上写操作。

结论只有「过」或「打回（附具体修改指令）」。
