# 总控模式踩过的坑

来自一个 iOS + 服务端项目两周的实际运行。数字是当时的真实记录，用来说明代价量级。

每条：现象 → 对策。新项目不必一开始全加，碰到同类症状时来这里查。

## 角色与审查
- **工人放宽断言让测试变绿**：SE 小屏上 Tab 栏出屏，工人把断言改松就「过了」。→ 审查员必须是另一个代理，审查清单专列「有没有为变绿放宽断言」；打回意见写具体到文件和验法。
- **反复返工耗额度**：同一问题来回四五轮。→ 打回一次；第二次仍不过就停，报用户决定。
- **状态混淆**：「代码写完」被当成「能用了」，栽过好几次。→ 分清已实现 / 已测试 / 已合并 / 已部署 / 线上已验证，看板和通知都按这五档写。

## git 与 worktree
- **`git checkout -- <file>` 抹掉别人未提交的 83 条文案**。→ 禁用 checkout / restore / reset --hard；撤销自己的改动先 cp 备份。只有总控 commit。
- **worktree 基点错**：好几次 worktree 被建在旧分支上。→ 提示词写基点 commit，工人开工第一步 `git log -1` 核对，不符就停。
- **派工时主目录有未提交改动**：worktree 从 HEAD 分出，看不到，合回来冲突。→ 派工前主目录必须已 commit。
- **续做派了新工人，零产出**：新工人被隔离在自己的 worktree，进不去别人的目录。→ 续做只能 SendMessage 原工人。
- **worktree 里的成果没回流**：代码合了，文案留在 worktree 里，界面显示 key 名。→ 合并时核对 diff 覆盖所有产物（代码、资源、翻译）。
- **大 JSON 全量重写**：两万行的 xcstrings 被 json.dumps 重排，上万行 diff 埋掉别人的改动。→ 这类文件只按 key 追加。

## 资源与额度
- **一天 88 个子代理、12 亿缓存读取**，前十个占 62%。→ 每个工人任务写命令上限（80）和 token 预算；到 80% 让它收尾交活；逐条处理数据的活强制「写脚本一次跑」。
- **测试日志读进上下文**，一份 xcodebuild 日志就几万 token。→ 输出一律重定向到 build-*/，只读 grep 汇总 + tail。
- **多台模拟器同时开机卡死两小时，拖垮 CPU**。→ 重活经 build-slot 排队（全机 2 个名额），用完自动关模拟器。
- **磁盘满（剩 141 MB）**：各 worktree 的构建产物堆积。→ 定期清 worktree 下的 DerivedData 类目录；收尾时统一清 worktree。
- **宽匹配 `pkill -f swift-test` 误杀别人的测试**。→ 只按自己的 PID 精确 kill。
- **全量 UI 回归太贵**：每次修复都跑全量。→ 修复只跑自己碰到的测试类；全量只在里程碑（所有修复做完、出包前）由总控跑。

## 决策与记录
- **过期状态文档让规划跑偏好几轮**（以为登录没通，实际早通了）。→ 判断「什么能用」查系统，不读旧文档；台账写「依据」一栏。
- **同一问题反复讨论**。→ 台账只增不改，已拍板的一律沿用；推翻属于硬停，要用户点头。
- **顾问的判断标准越积越准**：用户每拍一次板，把背后的标准补一条进 advisor.md，后面顾问就能替他做同类判断。
- **用户不在电脑前**：只在对话里说的事用户看不到。→ 要用户做的、要拍板的，出现即推通知；每完成一件推【完成】【剩余】。
- **上下文压缩丢工人状态**。→ 压缩前 commit + push、把每个工人停点写进看板；CLAUDE.md 的 Compact Instructions 写明必须保留什么；压缩后第一件事重读看板。

## 部署与线上
- **部署了未合并的代码**，线上与仓库对不上。→ 只部署主目录已合并的 commit；部署前备份、比 sha、写回滚；记 DEPLOYED_COMMIT。
- **线上 SQL 误写**。→ 一律只读事务包起来，除非任务本身就是迁移。
- **密钥进了对话 / 日志**。→ 密钥只由用户写进文件或密钥库；通知、日志、提示词里一律不出现。
